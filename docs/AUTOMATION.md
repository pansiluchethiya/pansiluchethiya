# Automation

Everything on the profile README is generated by GitHub Actions. The repository holds
the *inputs* (configuration, data pools, scripts) and the *outputs* (the SVG cards that
the README embeds). Nothing has to be edited by hand after the initial setup.

## Scheduled jobs

| Workflow | Schedule | What it does |
|:--|:--|:--|
| [`dynamic-content.yml`](../.github/workflows/dynamic-content.yml) | hourly, `5 * * * *` | Picks a new developer quote and a new fun fact and re-renders `assets/developer-quote.svg` and `assets/fun-fact.svg`. |
| [`snake.yml`](../.github/workflows/snake.yml) | daily, `17 0 * * *` | Regenerates the animated contribution snake and publishes it to the `output` branch. |
| [`profile-update.yml`](../.github/workflows/profile-update.yml) | daily, `23 3 * * *` | Re-reads the GitHub API, re-renders the stats cards, refreshes the featured projects and rewrites the README blocks. |
| [`wakatime.yml`](../.github/workflows/wakatime.yml) | every 6 hours, `41 */6 * * *` | Refreshes the WakaTime card (skipped automatically when no API key is configured). |
| [`validate.yml`](../.github/workflows/validate.yml) | on push and pull request | Validates JSON, SVG, YAML, Markdown, privacy rules and secret hygiene. |

All of them also support **Run workflow** from the Actions tab, so any card can be
regenerated on demand.

## Why the numbers are not hard-coded

`scripts/generate_stats.py` and `scripts/generate_projects.py` read everything from the
GitHub API (REST + GraphQL) using `secrets.GITHUB_TOKEN`. The rendered values live in
`data/profile.json` and `data/projects.json`, and the cards in `assets/` are rebuilt from
those files on every run. The README itself only contains static markup plus the two
generated blocks, so it stays readable in a text editor and in the GitHub API.

GitHub proxies README images through its camo cache, which is why every generated asset
reference carries a `?v=<hash>` query string. The hash changes whenever the asset
changes, so a refreshed card is visible immediately instead of after the cache expires.

## Repository layout

```
.github/workflows/   scheduled automation
scripts/             generators (standard library Python only)
config/              hand-edited configuration: profile identity, featured projects
data/                generated data (profile.json, projects.json) and curated pools
assets/              generated SVG cards that the README embeds
docs/                this file
```

## The fun fact pool

`data/fun-facts.json` holds 500 vetted facts that were extracted from Wikipedia's
"Did you know" archive and filtered for length, formatting and content. The pool is
committed to the repository, so the README never depends on a third-party API being
online. `scripts/generate_fun_fact.py` selects a fact deterministically from the current
UTC hour, which means the card changes hourly without any API traffic.

To rebuild the pool from scratch:

```bash
python scripts/fetch_fun_facts.py --target 500
```

## The quote pool

`data/quotes.json` holds curated developer quotes with authors.
`scripts/generate_quote.py` picks one per UTC hour and renders it as an SVG card.

## The snake

`snake.yml` runs [`Platane/snk`](https://github.com/Platane/snk) with the `github-dark`
palette and pushes the result to the **`output` branch** of this repository. The README points
at that branch and the card is regenerated every day.

The `output` branch is generated content — do not commit to it by hand.

## WakaTime

The WakaTime section is connected. The API key lives in the repository secret
`WAKATIME_API_KEY` (never in the code) and `scripts/generate_wakatime.py` uses it to render
`assets/wakatime.svg` every six hours.

The card is built from the **durations** endpoint rather than the statistics endpoint, because
WakaTime's statistics endpoints only count human coding time — accounts whose sessions are
tracked as AI coding report `0` there even though the dashboard shows real hours. The card
shows the total coding time, the daily average, the most active day, and the language and
editor breakdown when the sessions carry that metadata.

To use a different WakaTime account, replace the secret:

```bash
gh secret set WAKATIME_API_KEY --body "waka_..."
```

The username is resolved automatically through `/users/current`; set a username in your
WakaTime profile settings and it starts appearing on the card.

## Private repositories

Featured projects that are private are rendered with a title, a `🔒 private` marker and a
generic one-line description. No private repository slug, owner, description, language or
URL is ever fetched into the generated data or written to the README.
`scripts/validate.py` fails the build if a private identifier appears in any tracked file.

## Running the generators locally

```bash
export GITHUB_TOKEN="$(gh auth token)"
python scripts/generate_stats.py      # stats cards -> assets/*.svg, data/profile.json
python scripts/generate_projects.py   # project metadata -> data/projects.json
python scripts/generate_quote.py      # assets/developer-quote.svg
python scripts/generate_fun_fact.py   # assets/fun-fact.svg
python scripts/update_readme.py       # rewrites the README blocks
python scripts/validate.py            # local validation
```

`scripts/generate_wakatime.py` needs `WAKATIME_API_KEY` and exits cleanly when the
variable is not set.

## Editing the featured projects

`config/projects.json` is the only file to touch when the project list changes:

```json
{
  "title": "Blink",
  "repo": "Blink",
  "live_label": "live demo",
  "tech": ["TypeScript", "React", "Socket.IO"]
}
```

`repo` is the public repository name, `frontend_repo` optionally points at a companion
frontend repository, and a project marked `"private": true` is rendered without any
repository metadata. The next `profile-update` run picks the change up and rewrites the
README table.
